一顆會跑回合的
遊戲核心

gamecore-zone 是 gamecore 三層架構（World／Region／Area）的最底層——區域層。 它用 C++ 寫的 ECS 跑出一張地圖、一個英雄、一群會追你的 NPC， 並提供三種可即時切換的回合排程器，全部接到 Godot 前端可以實機操作。

這是什麼

把「時間怎麼流動」做成可以換的零件

大部分回合制遊戲把時間規則寫死。這個核心反過來：同一份遊戲世界，三套不同的時間模型隨按 TAB 切換， 讓你能直接比較「能量瞬發」「能量＋詠唱」「純 tick」三種排程在同一場戰鬥下的差異。所有戰鬥效果、持續傷害、技能都是資料驅動的。

核心能力

裡面有哪些系統

⟳

三種回合排程器

A 能量瞬發、B 能量＋可打斷詠唱（最完整）、C 純 tick。執行中按 TAB 即時切換比較。

✦

資料化技能

火球／治療／隕石／劇毒等技能寫在 data/actions.json，由可組合原語（位移／nova／DoT／自療）拼出。

☣

持續效果 DoT

燃燒、中毒、回復在每回合開始結算；致死會發 ActorDied 事件，nova 會對生還者殘留燃燒。

⚔

NPC 追擊 AI

NPC 朝英雄移動、相鄰即撞擊攻擊；半數是施法者，逼近就放 nova 技能圍殺。

◫

診斷面板 + Trace

逐 actor 傾印 HP／能量／進行中動作／所有持續效果；trace 管線把每件事發生當下吐成文字。

⇄

GDExtension 接線

C++ 核心編成原生擴充，GDScript 前端用 submit／step 驅動；存讀檔 round-trip 已驗證。

做了什麼 · 開發歷程

從 hard fork 到可玩 demo

以下是這條分支實際走過的路。每一步都跟著測試綠燈與 headless 驗證前進。

STEP 01 · 重構

zone_core hard fork

自 opennefia-cpp 砍出區域層，保留 ECS／FOV／戰鬥，移除 OpenNefia 特有機制（事件匯流排、原型管理器）。25→ctest 全綠。

STEP 02 · 接線

GDExtension 建置通過

zone_gd 編譯成原生擴充，Godot headless VERIFY PASSED：60×40 地圖、save/load round-trip 全綠。

STEP 03 · 設計

回合迴圈 §7 + Action 模型定案

收斂出對稱 actor 模型與 order 表；定案 Action＝enum＋param＋weight、時間用 ToME4 能量、效果走可替換 on_channel／on_resolve。

STEP 04 · 實作

三排程器 + 真實效果

純 core 寫出 A／B／C 三排程器與移動／撞牆／攻擊／拾取效果，接進 ZoneWorld（additive，不動既有 move）。

STEP 05 · 前端

Timer 驅動 + 即時打斷 + Cast

map_view 改 Timer 推進、輸入只 submit；新增詠唱技能與「詠唱中按移動＝即時打斷」。

STEP 06 · 系統

DoT + JSON 技能 + NPC 智能

持續傷害系統、actions.json 資料化技能、NPC 追擊與施法者；最終 ctest 49 案／168 斷言全綠。

STEP 07 · 工具

診斷 UI + Trace + 真 bug 修復

詳細 debug 面板與 trace log；修掉玩家致死雙重 destroy 崩潰、verify.gd 假通過、CJK 亂碼等真實 bug。
