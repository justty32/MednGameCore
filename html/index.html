一顆最精簡的
傳統回合制核心

gamecore-zone 是 gamecore 三層架構（World／Region／Area）的最底層——區域層。 它用 C++ 寫的 ECS 跑出一張地圖、一個英雄、一群會追你的 NPC， 提供乾淨的傳統回合制地基（移動、撞擊攻擊、拾道具、下樓梯），全部接到 Godot 前端可以實機操作。

這是什麼

一個乾淨、教科書式的回合制地基

不堆機制、不搶先做花俏系統。這個核心刻意做到最傳統、最精簡：一條按加入序排列的 actor 名單、 玩家輪到時阻塞等輸入、NPC 朝你追擊、撞進有人的格子＝攻擊。能量制／詠唱／技能／狀態效果都被刻意移除， 留作建立在這個地基之上的未來擴充。

核心能力

裡面有哪些系統

⟳

TurnEngine 回合引擎

一條按加入序排的 actor 名單，begin_round() 後反覆 step() 到回合結束。純 core、不持有 registry，好測。

⚔

撞擊攻擊

沒有獨立的攻擊指令：移動進入有 actor 的格子＝攻擊，扣攻擊力傷害，致死發 ActorDied。

◆

act_point 行動值

每 actor 本回合首次輪到時 ActPointComponent 重設為 1000、行動後歸 0。為「未來依成本行動多次」預留。

⌖

NPC 追擊 AI

decide_chase()：朝英雄移動一格，相鄰即撞擊攻擊；無目標則等待。最精簡的敵人腦。

◫

診斷面板 + Trace

傾印逐 actor 的 HP、回合數、樓層、NPC 數；trace 管線把每件事發生當下吐成文字。

⇄

GDExtension 接線

C++ 核心編成原生擴充，GDScript 前端按一鍵＝英雄行動一次＋整輪 NPC；存讀檔 round-trip 已驗證。

做了什麼 · 開發歷程

從 hard fork 到可玩 demo

以下是這條分支實際走過的路。每一步都跟著測試綠燈與 headless 驗證前進。

STEP 01 · 重構

zone_core hard fork

自 opennefia-cpp 砍出區域層，保留 ECS／FOV／戰鬥，移除 OpenNefia 特有機制（事件匯流排、原型管理器）。25→ctest 全綠。

STEP 02 · 接線

GDExtension 建置通過

zone_gd 編譯成原生擴充，Godot headless VERIFY PASSED：60×40 地圖、save/load round-trip 全綠。

STEP 03 · 探索

能量排程器實驗

曾實驗「三種可切換排程器（能量瞬發／能量＋詠唱／純 tick）＋資料化技能＋DoT」。實驗證明設計空間，但對地基而言太重。

STEP 04 · 前端

GDExtension 接線打通

zone_gd 編成原生擴充，map_view 把鍵盤接到核心、ASCII 畫面與 debug 面板成形，headless 驗證綠。

STEP 05 · 工具

診斷 UI + Trace + 真 bug 修復

詳細 debug 面板與 trace log；修掉玩家致死雙重 destroy 崩潰、verify.gd 假通過、CJK 亂碼等真實 bug。

STEP 06 · 重構（2026-06-21）

回合系統重構為最簡 TurnEngine

刻意大幅簡化（淨刪約 1300 行）：整套能量排程器／詠唱／JSON 技能／DoT／nova 全部移除，重建為教科書式 TurnEngine＋apply_action＋decide_chase。前端改 next_round／player_move／player_wait。doctest 29 案／93 斷言全綠。
