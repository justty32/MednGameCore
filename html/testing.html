測試與驗證

怎麼確認它真的能跑

三層驗證，由快到慢、由純到實：① 單元測試（純 C++，最快）→ ② headless 端到端（Godot 不開視窗，地城與戰棋各一支腳本）→ ③ 實機操作（開視窗自己玩）。指令框可點擊複製。

先決條件

你需要什麼

⚙

CMake ≥ 3.14

＋ 支援 C++20 的編譯器。相依套件（EnTT／cereal／doctest）由 FetchContent 自動抓。

🎮

Godot 4.6（mono）

僅 ② ③ 需要。GDExtension 相容版本 ≥ 4.4。

🌐

網路（首次建置）

第一次 cmake 會下載相依原始碼，之後就快取在 build/ 裡。

第一層 · 最快

① 純 C++ 單元測試（doctest）

不需要 Godot。這會驗證地城的 TurnEngine 回合流程、apply_action 結算、decide_npc 決策，以及戰棋的行動條、可達集、回合子狀態機與 AI 的核心邏輯。

設定 + 建置核心測試（務必限制並行）
# 在 repo 根目錄；含 GDExtension 開關
$ cmake -S . -B build -DZONE_BUILD_GDEXTENSION=ON
$ cmake --build build --target zone_test -j4
為什麼要 -j4（不要裸 -j） 曾因無上限 -j 同時開出約 541 個編譯程序，瞬間耗盡 60GiB RAM 觸發 OOM 強制重啟。 建置這個專案務必限制並行，例如 -j4，別用裸 -j。這是本專案第一鐵律。
跑全部測試
# 直接執行測試二進位
$ ./build/bin/zone_test
# 或透過 ctest
$ ctest --test-dir build --output-on-failure
預期結果 55 個測試案例 · 236 個斷言 · 全綠。 test_turn_engine.cpp / test_npc_combat.cpp 涵蓋地城回合與撞擊/追擊； test_tactics.cpp 涵蓋戰棋核心 22 案：行動條出手序與溢出保留、可達集阻擋規則、 射程與敵我判定、AI 排序鍵、回合子狀態機、AI 打完整場不卡死。

想針對單一機制，可用 doctest 的子集過濾：

$ ./build/bin/zone_test --test-case="*turn_engine*"
$ ./build/bin/zone_test --test-case="*apply_action*"
$ ./build/bin/zone_test --test-case="*tactics*"

第二層 · 端到端

② Godot headless 驗證（不開視窗）

這會真的載入原生擴充 libzone_gd.so，驗證 C++ ↔ Godot 整條接線。現況有兩支驗證腳本——地城與戰棋各一——都以機器人跑完整局後斷言必達結局。

建置 GDExtension（同樣限制並行）
$ cmake -S . -B build -DZONE_BUILD_GDEXTENSION=ON
$ cmake --build build --target zone_gd -j4
# 建置後會自動把 libzone_gd.so 複製到 godot_zone/bin/（POST_BUILD）
先 import 一次，再跑兩支驗證腳本
# 首次需先 import 建立 .godot/extension_list.cfg
$ godot-mono --headless --path godot_zone --import
# 地城
$ godot-mono --headless --path godot_zone -s res://verify.gd
# 戰棋
$ godot-mono --headless --path godot_zone -s res://verify_tactics.gd
預期結果 · 地城 verify.gd 用固定種子的 BFS 尋路機器人一路殺向樓梯，斷言遊戲必達結局（通關或戰死）、 至少到第 2 層、且過程中英雄有掉血，並檢查 get_tile_flags()／get_visible_entities() 欄位， 最後印 VERIFY PASSED。
預期結果 · 戰棋 verify_tactics.gd 用固定種子機器人（能打就打、否則走向最近敵人）打完一整場，斷言必達勝負、 battle_over signal 與 get_winner() 一致、移動/攻擊/死亡事件皆至少發生一次、戰鬥結束後不再接受指令， 最後印 TACTICS VERIFY PASSED。
綠燈也要看它驗的是不是你以為的東西 早期 verify.gd 的等待迴圈曾在 submit 後英雄「仍在 waiting」時直接跳過——指令從沒被執行卻顯示通過。 現版改用真正推進回合的 BFS 機器人斷言到英雄移動與掉血才算數。假通過比紅燈更危險。

第三層 · 自己玩

③ 開視窗實機操作

main scene 現在是 main_menu.tscn：開遊戲後由主選單選「地城探索」或「戰棋對戰」進入兩個平行場景之一。

啟動
$ godot-mono --path godot_zone
# 主選單 main_menu.tscn → 選 地城探索 / 戰棋對戰

地城探索 — 操作對照表

最傳統回合制：按一鍵＝英雄行動一次＋本輪所有 NPC 行動一輪。

按鍵動作觀察什麼
W A S D / 方向鍵 / 數字鍵(KP1-9)八方向移動（英雄行動＋整輪 NPC）撞牆停住、撞到敵人＝攻擊
按住方向鍵超過 0.5 秒後每 0.08 秒自動走一格撞牆/攻擊/被攻擊/拾取/下樓/新怪入視野都會中斷
. / KP5原地等待一回合世界推進、看 NPC 逼近

建議的驗證劇本

A

地城 · 看回合順序

移動或 . 等待，開 Tab 盯 trace——英雄（加入序最先）先動，接著本輪所有 NPC 依序行動一輪。

B

地城 · 看撞擊攻擊

朝相鄰 NPC 走一步＝攻擊，看它 HP 下降；致死時發 npc_died，目標從名單移除。

C

地城 · 下樓成長

一路殺向樓梯，走下第 5 層即通關；每下一層英雄成長（最大 HP／治療／攻擊），否則數學上打不贏。

⚔

戰棋 · 移動＋攻擊

點藍格走位，再點紅框敵人攻擊——攻擊後回合立即結束；殲滅一方即分勝負。看快角偶爾連動兩次。
