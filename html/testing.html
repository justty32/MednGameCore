測試與驗證

怎麼確認它真的能跑

三層驗證，由快到慢、由純到實：① 單元測試（純 C++，最快）→ ② headless 端到端（Godot 不開視窗）→ ③ 實機操作（開視窗自己玩）。 指令框可點擊複製。

先決條件

你需要什麼

⚙

CMake ≥ 3.14

＋ 支援 C++20 的編譯器。相依套件（EnTT／cereal／doctest）由 FetchContent 自動抓。

🎮

Godot 4.6（mono）

僅 ② ③ 需要。GDExtension 相容版本 ≥ 4.4。

🌐

網路（首次建置）

第一次 cmake 會下載相依原始碼，之後就快取在 build/ 裡。

第一層 · 最快

① 純 C++ 單元測試（doctest）

不需要 Godot。這會驗證 TurnEngine 回合流程、apply_action 結算、NPC 決策的核心邏輯。

建置核心 + 測試（務必限制並行）
# 在 repo 根目錄
$ cmake -B build
$ cmake --build build --target zone_test -j4
為什麼要 -j4（不要裸 -j） 曾因無上限 -j 同時開出約 541 個編譯程序，瞬間耗盡 60GiB RAM 觸發 OOM 強制重啟。 建置這個專案務必限制並行，例如 -j4，別用裸 -j。
跑全部測試
# 直接執行測試二進位
$ ./build/bin/zone_test
# 或透過 ctest
$ ctest --test-dir build --output-on-failure
預期結果 29 個測試案例 · 93 個斷言 · 全綠。 test_turn_engine.cpp 涵蓋：加入序＝回合序、每 actor act_point 重設 1000、玩家阻塞 submit 後續跑、撞 actor 致死發 ActorDied，以及序列化 round-trip。

想針對單一機制，可用 doctest 的子集過濾，例如只跑回合引擎相關：

$ ./build/bin/zone_test --test-case="*turn_engine*"
$ ./build/bin/zone_test --test-case="*apply_action*"

第二層 · 端到端

② Godot headless 驗證（不開視窗）

這會真的載入原生擴充 libzone_gd.so，驗證 C++ ↔ Godot 整條接線：建世界、player_wait 推進回合、player_move 移動、NPC 追擊致 HP 下降、save/load round-trip。

建置 GDExtension（同樣限制並行）
$ cmake -B build -DZONE_BUILD_GDEXTENSION=ON
$ cmake --build build --target zone_gd -j4
# 建置後會自動把 libzone_gd.so 複製到 godot_zone/bin/（POST_BUILD）
先 import 一次，再跑驗證腳本
# 首次需先 import 建立 .godot/extension_list.cfg
$ godot-mono --headless --path godot_zone --import
$ godot-mono --headless --path godot_zone -s res://verify.gd
預期結果 終端印出 zone core version: 0.0.1-alpha，依序驗證回合推進、四方移動、NPC 追擊致 HP 下降、trace、存讀檔 round-trip， 最後印 VERIFY PASSED。
這裡修過一個假通過 早期 verify.gd 的等待迴圈在 submit 後英雄「仍在 waiting」時直接跳過——指令從沒被執行卻顯示通過。 改成真正推進回合後才驗到英雄移動。提醒：綠燈也要看它驗的是不是你以為的東西。

第三層 · 自己玩

③ 開視窗實機操作

主場景 map_view.tscn。畫面上有 ASCII 地圖 + 詳細 debug 面板（逐 actor 的 HP、回合數、樓層、NPC 數）+ trace log。按一鍵＝英雄行動一次＋整輪 NPC。

啟動
$ godot-mono --path godot_zone
# 主場景就是 map_view.tscn，直接開始

操作對照表

按鍵動作觀察什麼
W A S D / 方向鍵 / 數字鍵移動一步（英雄行動＋整輪 NPC）撞牆停住、撞到敵人＝攻擊
. / KP5原地等待一回合世界推進、看 NPC 逼近
L開關 trace log 顯示每件事發生當下吐成文字
K清空 trace log—
R重開一局地圖、英雄、NPC 重新生成
F5 / F9存檔 / 讀檔驗證序列化 round-trip

建議的驗證劇本

A

看回合順序

移動或 . 等待，盯 trace——英雄（加入序最先）先動，接著本輪所有 NPC 依序行動一輪。

B

看撞擊攻擊

朝相鄰 NPC 走一步＝攻擊，看它 HP 下降；致死時發 npc_died，目標從名單移除。

C

看追擊與拾道具

原地 . 等待數回合，NPC 一路追近圍住你；移動踩到 ! 自動拾 health_potion 回血。

↓

看下樓梯

走到下樓梯格觸發換層，發 floor_changed，地圖與 NPC 重新生成，樓層數 +1。
