測試與驗證

怎麼確認它真的能跑

三層驗證，由快到慢、由純到實：① 單元測試（純 C++，最快）→ ② headless 端到端（Godot 不開視窗）→ ③ 實機操作（開視窗自己玩）。 指令框可點擊複製。

先決條件

你需要什麼

⚙

CMake ≥ 3.14

＋ 支援 C++20 的編譯器。相依套件（EnTT／cereal／doctest）由 FetchContent 自動抓。

🎮

Godot 4.6（mono）

僅 ② ③ 需要。GDExtension 相容版本 ≥ 4.4。

🌐

網路（首次建置）

第一次 cmake 會下載相依原始碼，之後就快取在 build/ 裡。

第一層 · 最快

① 純 C++ 單元測試（ctest）

不需要 Godot。這會驗證排程器、效果、DoT、技能載入、NPC 決策的核心邏輯。

建置核心 + 測試
# 在 repo 根目錄
$ cmake -B build
$ cmake --build build -j
跑全部測試
$ ctest --test-dir build --output-on-failure
# 或直接執行測試二進位
$ ./build/bin/zone_test
預期結果 49 個測試案例 · 168 個斷言 · 全綠。 涵蓋速度差、channel 詠唱、打斷、玩家阻塞、多角色、移動/撞牆/攻擊/拾取、Cast nova、DoT 逐回合/致死、 JSON 載入/後備、NPC 追擊/施法/方向，以及序列化 round-trip。

想針對單一機制，可用 doctest 的子集過濾，例如只跑排程器相關：

$ ./build/bin/zone_test --test-case="scheduler*"
$ ./build/bin/zone_test --test-case="timed_effect*"   # DoT
$ ./build/bin/zone_test --test-case="action_def*"     # JSON 技能

第二層 · 端到端

② Godot headless 驗證（不開視窗）

這會真的載入原生擴充 libzone_gd.so，驗證 C++ ↔ Godot 整條接線：建世界、三模式提交指令、save/load round-trip。

先帶 GDExtension 重新建置
$ cmake -B build -DZONE_BUILD_GDEXTENSION=ON
$ cmake --build build -j
# 產物 libzone_gd.so 需放到 godot 專案的 bin/
$ cp build/bin/libzone_gd.so godot_zone/bin/
跑驗證腳本
$ godot-mono --headless --path godot_zone -s res://verify.gd
預期結果 終端印出 zone core version: 0.0.1-alpha，依序驗證 三排程器 + cast + skill， 最後印 VERIFY PASSED。verify.gd 會 set_mode → submit → step 直到英雄真的動了才算過。
這裡修過一個假通過 早期 verify.gd 用 while not waiting 迴圈，但 submit 後英雄「仍在 waiting」，迴圈直接跳過——指令從沒被執行卻顯示通過。 改成 step-first 的 _advance() 後才真正驗到英雄移動。提醒：綠燈也要看它驗的是不是你以為的東西。

第三層 · 自己玩

③ 開視窗實機操作

主場景 map_view.tscn。畫面上有 ASCII 地圖 + 詳細 debug 面板（逐 actor 的 HP／能量／進行中動作／持續效果）+ trace log。

啟動
$ godot-mono --path godot_zone
# 主場景就是 map_view.tscn，直接開始

建議的驗證劇本

A

看速度差

切到 A 或 B，原地 . 等待，盯面板的 energy(spd) 欄——快角（spd130）比慢角（spd80）更常出手。

B

看詠唱與打斷

切 B，按 C 開始火球（▸channel x/3），蓄力中按移動——舊動作不結算，當場被打斷。

C

看純 tick

切 C，比較「誰下一個動」是否比能量制更好預測。

☠

看 DoT 致死

放火球/隕石點燃 NPC，按 . 等待，看燃燒每回合扣血直到歸零發出死亡。
