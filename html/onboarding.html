這是 gamecore 三層架構（World／Region／Area）最底層的區域層：一顆 C++17 / EnTT ECS 核心，外接 Godot 4.6 GDExtension（mono）前端。 裡頭是兩個平行、互不干涉的場景——最傳統的回合制地城探索 roguelike， 與 ToME4 行動值模型的 SRPG 戰棋戰鬥——共用 ECS／地圖／存讀檔基建， 由主選單擇一進入。

你懂 C++、Godot 摸過一點——這頁不教 ECS，只帶你認這個 repo：一條鐵律、兩套系統、 「改東西去哪」、怎麼跑、有哪些坑、還剩什麼沒收尾。

最重要的心智模型

兩套刻意分離的回合系統

改任何一邊之前，先確認自己站在哪個模組。兩者不共用、不互相依賴—— 地城側刻意保持「教科書式最簡」，戰棋側才是行動值排程。把它們混在一起是最大的認知陷阱。

地城探索 · Dungeon

TurnEngine ＋ 撞擊攻擊

  • 回合序＝加入序，英雄最先。begin_round() 後反覆 step() 到回合結束；玩家阻塞等 submit()，NPC 立即 decide()。
  • 沒有獨立攻擊動作——移動進入有 actor 的格子就是攻擊（apply_action）。
  • NPC 用 decide_npc()：LOS 警覺＋記憶、相鄰即攻、避牆避人。
  • 勝利＝走下第 5 層樓梯；每下一層英雄成長，否則數學上打不贏。
  • 橋樑：ZoneWorld。前端：map_view.gd + dungeon_view.gd。
核心：src/core/turn/  ·  橋樑：src/gbind/zone_world_gd.cpp
戰棋戰鬥 · Tactics

ActionBar ＋ 單位子回合

  • ToME4 行動值：kCtToAct=1000，每 tick ct += speed；出手後 ct -= 1000（不歸零，溢出保留，快角偶爾連動兩次）。
  • 可達集＝四方向 BFS，牆與其他單位佔格皆阻擋（不能穿、不能停）。
  • 一個單位的回合＝移動一次＋行動一次，攻擊即結束回合（Battle 子狀態機）。
  • AI decide_tactics()：射程內打最脆目標，否則走到「進得了射程但不貼身」的格子。
  • 橋樑：TacticsBattle : Node。前端：tactics_view.gd + arena_view.gd。
核心：src/core/tactics/  ·  橋樑：src/gbind/tactics_battle_gd.cpp

跑起來

建置、測試、實機

▲ 建置第一鐵律：一律加並行上限 -j4（或更低）。 曾因無上限 -j 同時起約 541 個編譯程序吃光 60 GiB RAM 觸發 OOM 強制重啟。這條沒得商量。

C++ 核心 / 測試

# 設定（含 GDExtension）
cmake -S . -B build -DZONE_BUILD_GDEXTENSION=ON

# 核心測試（55 case / 236 assertion）
cmake --build build --target zone_test -j4
./build/bin/zone_test   # 或 ctest --test-dir build

# 建 GDExtension（自動複製 .so 到 godot_zone/bin/）
cmake --build build --target zone_gd -j4

Godot 前端 / 端到端驗證

# 首次需 import 一次
godot-mono --headless --path godot_zone --import

# 開遊戲（main scene = main_menu.tscn）
godot-mono --path godot_zone

# headless 端到端驗證
… -s res://verify.gd          # VERIFY PASSED
… -s res://verify_tactics.gd  # TACTICS VERIFY PASSED

CMake 目標：zone_core（STATIC，godot-free）· zone_test（doctest）· zone_gd（SHARED，連結 zone_core + godot-cpp）。 godot-cpp 在 repo 外 ../../projects/godot-cpp，可用 -DGODOT_CPP_DIR 覆寫。

別踩的坑

接手前必知的四個地雷

01 無上限 -j 會炸機器

本專案第一鐵律，見上一節。任何 cmake --build 都加 -j4。

02 TurnEngine 不是佔位品

2026-06-21（e9ed694）已完成整套重寫，收斂成最傳統回合制是設計目標。 行動條／能量制刻意另開 src/core/tactics/——不得加回 TurnEngine。

03 存檔元件唯一真相來源

新增或刪除任何可序列化 component，務必同步 src/core/serialize/all_components.h，否則存讀檔會悄悄壞掉。

04 核心不得認識 Godot

#include <godot_cpp/…> 只能出現在 src/gbind/。 src/core/ 若沾到 Godot header，就破壞了可單元測試的地基。
