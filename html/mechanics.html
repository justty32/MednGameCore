機制詳解

內部到底怎麼運作

四塊核心機制：三種排程器差在哪、技能怎麼用資料拼出來、 DoT 何時結算、NPC 怎麼決定下一步。每塊都標了對應的測試案例方便對照。

招牌功能

三種回合排程器（TAB 切換）

同一個世界，三套時間模型。執行中按 TAB 即時切換，直接比較同場戰鬥下的行為差異。

⚡

EnergyInstant

純 ToME4 風格：每 tick 給能量，能量夠就瞬間出手並扣行動值成本。沒有詠唱概念，最單純。

⟳

EnergyChannel

能量排程 ＋ 可打斷的詠唱（channel）。weight>1 的動作要跨多回合蓄力，蓄力中可被新指令打斷。最完整，前端預設。

⏱

TickRemaining

沒有能量概念：每回合整步前進，跳到下一個結算點。最容易推理「誰下一個動」。

資料驅動

技能＝一組可組合原語

沒有一個技能是寫死的。每個技能由 data/actions.json 的欄位拼出來，C++ 端只認得這幾種原語：

data/actions.json — fireball 條目
{
  "name": "fireball", "weight": 3,   // 詠唱 3 回合
  "nova_damage": 4, "radius": 1,    // 對周圍 1 格 nova 4 傷
  "dot_turns": 3, "dot_power": 2, "dot_kind": 0,  // 殘留燃燒 3 回合
  "self_heal": 0, "self_regen_turns": 0
}
技能鍵weight效果
fireballC3nova 4（r1）＋燃燒 3 回合
healH2瞬補 8 ＋ Regen buff 3 回合（可見）
meteorM4大範圍 nova 5（r2）＋燃燒 2 回合
venomV2nova 1 ＋中毒 5 回合（毒系 DoT）
smite—1nova 6，瞬發無 DoT
npc_flameNPC1施法者 NPC 專用 nova 3 ＋燃燒
後備機制 若 actions.json 載入失敗，C++ 會呼叫 load_defaults() 內建一份備援技能庫，遊戲不會因缺檔崩潰。 這兩條路徑都有測試覆蓋（JSON 載入案 + 後備案）。

持續效果

DoT：每回合開始結算

持續效果掛在 TimedEffectsComponent 上，三種類型：

🔥

Burning 燃燒

火球／隕石殘留。每回合扣血，過期消失。

☠

Poison 中毒

venom 施加。較長持續、低額逐回合傷害。

✚

Regen 回復

heal 附帶。每回合回血，是個正向 DoT。

這裡藏過一個真 bug DoT 致死會 destroy 任何 actor——包含英雄。早期版本英雄被 DoT 燒死後，restart 又 destroy 一次造成雙重 destroy 崩潰。 修法：die() 保護 PlayerControlled 不被消滅（只觸發 game over），三排程器在 actor 取得回合前都重檢 reg.valid 防越界。

結算時機由 TurnWorld.on_actor_turn hook 驅動：actor 一拿到回合，先跑 tick_timed_effects（扣血／過期／致死發 ActorDied），再執行它的動作。

敵人 AI

NPC 怎麼決定下一步

核心邏輯在 npc_brain.cpp 的 decide_chase()，放在 core 所以能直接 ctest（不用開 Godot）。

decide_chase 決策樹
每個 NPC 取得回合時： 與英雄相鄰？ ├─ 是 ──┬─ 一般 NPC → 撞擊攻擊（朝英雄走＝攻擊） │ └─ 施法者 → 放 npc_flame nova 技能 │ └─ 否 ──── 朝英雄方向移動一格（追擊） # 半數 NPC 在 spawn 時被設為 caster（is_caster） # 速度差：caster 80 / 近戰 130 → 能量面板看得到行動值差
實機驗證過 headless demo：英雄原地等待 40 回合，被 NPC 圍殺 hp 20→0，證實追擊 + 施法者 nova 一起運作。 對應 4 個 test_npc_brain 測試案（方向正確／相鄰撞擊／施法者放技能／遠距仍移動）。
