機制詳解

內部到底怎麼運作

三塊核心機制：TurnEngine 怎麼跑一輪、apply_action 把一個動作結算成什麼、 NPC 怎麼決定下一步。這是刻意做到最精簡的傳統回合制地基。

核心

TurnEngine：一輪怎麼跑

維護一條 actor 的 std::list<entt::entity>，順序＝加入序（hero 最先加入，故每回合最先行動）。begin_round() 後反覆 step(ctx) 直到 RoundDone。

1
≡

actor list ＝ 加入序

沒有先攻、沒有速度排序。誰先 add_actor 誰先動。remove_actor 安全處理 cursor，死亡才從名單移除。

2
◆

act_point 行動值

每 actor 本回合首次輪到時 ActPointComponent.value 重設為 kActPointFull = 1000，行動後歸 0。目前一回合一次，為未來依成本多次行動預留。

3
⏸

依操控者分派

看 ControllerComponent.kind：Player 回 WaitingPlayer 暫停等 submit()；Self／Faction 立即 ctx.decide() 取動作並 ctx.resolve()。

概念內容
StepResultActed / WaitingPlayer / RoundDone
EngineCtxregistry& reg ＋ decide / resolve / trace 三個 callback。registry 不由引擎持有，保持引擎純粹可測。
list 維護add_actor（重複略過）/ remove_actor / contains / clear / order() / size()
Action{ ActionKind kind; int param; }，工廠 idle()/wait()/move(dir)。沒有 Attack、沒有技能／詠唱。Move 時 param 是方向編碼。
玩家阻塞 輪到 Player 操控者時 step() 回 WaitingPlayer 暫停（即 act() 阻塞等玩家），等 submit(e, action) 後才續跑。 多角色時依加入序逐一行動；Self／Faction（Faction 暫等同 Self）則立即解算，不暫停。

結算

apply_action：一個動作變成什麼

apply_action(reg, map, self, action, events) 把單一 Action 結算到世界並發出 ZoneEvent。沒有獨立攻擊指令——移動進入有 actor 的格子就是攻擊。

動作 / 情況結果發出的事件
Move → 撞牆 / 出界停住不動BumpedWall
Move → 撞到 actor（致死）扣 CombatStatsComponent.attack 傷害，目標死亡ActorDied
Move → 撞到 actor（未死）扣傷害，目標存活BumpedActor
Move → 空格（踩到道具）移動，自動拾取 health_potion 回血ItemPickedUp
Move → 踩到下樓梯移動，觸發下樓ReachedStairDown
Wait / Idle消耗回合，不做事—
死亡由呼叫端統一移除 被殺的目標只發 ActorDied 事件、不在此 destroy，由呼叫端（ZoneWorld）統一從 registry 與 actor list 移除。 這避免了「被殺者在同一輪後續又被存取」的越界問題。events 參數可為 null（純 core 測試時可不收事件）。

方向編碼在 move_dir.h：encode_dir(dx,dy) / decode_dir(p,dx,dy)，方向 0..8（八方向＋原地）。

敵人 AI

NPC 怎麼決定下一步

核心邏輯在 apply_action.cpp 的 decide_chase()，放在 core 所以能直接用 doctest（不用開 Godot）。這是最精簡的 NPC 腦。

decide_chase 決策
每個 NPC（ControllerKind::Self）取得回合時： 有目標（英雄）嗎？ ├─ 沒有 ── Action::wait()（原地等待） │ └─ 有 ──── 朝 target 移動一格 └─ 相鄰時這一步就是 撞擊攻擊 （移動進入英雄的格子＝攻擊） # 沒有施法者、沒有 nova、沒有速度差——就是純追擊 # ZoneWorld 的 npc_decide(e) 直接呼叫 decide_chase 追英雄
實機驗證過 headless demo：英雄原地等待，NPC 一路追擊逼近並撞擊攻擊，hero HP 下降，證實追擊與撞擊攻擊一起運作。 test_turn_engine.cpp 涵蓋：加入序＝回合序、每 actor act_point 重設 1000、玩家阻塞 submit 後續跑、撞 actor 致死發 ActorDied。
未來可選擴充 能量制／先攻排序／詠唱／資料化技能／狀態效果（DoT）／施法者 NPC 等，都是建立在這個最簡 TurnEngine 之上的未來方向， 設計探索保留在 workflows/idea/，目前都不在程式中。
