怎麼看程式

不會迷路的閱讀順序

這頁告訴你：整體架構長怎樣、每個資料夾負責什麼、哪幾個檔案才是「真相層」， 以及如果你只有五分鐘該打開哪三個檔案。

大圖

它在整個 gamecore 的哪一層

gamecore 規畫成三層，由大到小。這個 repo 只做最底層——區域層（Area Layer），也就是「你實際站在一張地圖上戰鬥」的那一層。

gamecore 三層架構
World Layer 世界／全域時間、大地圖 │ Region Layer 區域群、跨地圖移動 │ Area Layer ◀── 本 repo（gamecore-zone） 一張地圖 · ECS · FOV · TurnEngine · 戰鬥
出身 本層是從 opennefia-cpp hard fork 出來的：保留了成熟的 ECS／FOV／戰鬥骨架， 但把 OpenNefia 特有的機制（事件匯流排、原型管理器、spawn 系統）整套拿掉，換上自己最精簡的傳統回合制引擎。

真相層

哪些檔案是「設計的權威來源」

程式碼會變，但設計意圖寫在文件裡。要理解「現在怎麼跑」與「為什麼這樣設計」：

檔案它回答什麼問題
src/core/turn/turn_engine.h現況真相：actor list、begin_round/step、Player 阻塞 vs Self 立即解算
src/core/turn/apply_action.{h,cpp}現況真相：移動／撞牆／撞擊攻擊／拾取／下樓梯怎麼結算、decide_chase
SESSION-LOG.md逐步做了什麼、每個決策的理由、踩過哪些坑（最快的上手入口）
workflows/idea/、workflows/specs/archive/、workflows/plans/archive/歷史設計與未來方向：能量制／詠唱／技能／狀態效果等已移除實驗的設計探索，重新定位為「建立在 TurnEngine 之上的未來可選擴充」

資料怎麼流

一次玩家輸入發生了什麼

前端永遠不直接改世界，只「提交指令」，規則全在 C++。按一鍵＝英雄行動一次＋整輪 NPC 行動一輪。

一次「按 D 往右走」的資料流
[GDScript] map_view.gd 按下 D │ world.player_move(1, 0) # 若未在回合中先自動開一輪 ▼ [GDExtension] zone_world_gd.cpp 輪到英雄（WaitingPlayer）→ submit(hero, Move) │ pump()：反覆 step() 跑完整輪 NPC ▼ [C++ core] turn_engine.cpp / apply_action.cpp 英雄 resolve → apply_action(Move 1,0) │ NPC 們 decide_chase → apply_action 追擊 ▼ 撞牆？撞擊攻擊？拾取？下樓梯？ → 發 ZoneEvent + trace │ pump 到「玩家等待 / 回合結束 / 換樓層」才停 ▼ [GDScript] drain_events → signal → 重畫地圖 + 更新 debug 面板
關鍵設計 C++ 擁有規則、擁有時間；Godot 只負責「畫面 + 輸入 + 訊號」。 EngineCtx 把 registry 留在外面（引擎不持有 registry），引擎保持純粹可測。 玩家阻塞的定義 = 輪到 Player 操控者，step() 回 WaitingPlayer 暫停等 submit()，C++ 不空轉。
