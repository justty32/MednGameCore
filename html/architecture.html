程式結構

三層架構與分層鐵律

唯一鐵律：src/core/ 完全 godot-free，src/gbind/ 是唯一認識 Godot 的橋樑層。#include <godot_cpp/…> 只能出現在 gbind。

依賴方向：只能由上往下
godot_zone/ GDScript · 場景/輸入/畫面 │ ▼ src/gbind/ 唯一認識 Godot（ZoneWorld / TacticsBattle） │ ← #include <godot_cpp/…> 只到這裡 ▼ src/core/ 純 C++ / EnTT · 完全 godot-free · 可單元測試
改動守則 要在 core 加功能時，若需要 #include <godot_cpp/…>，代表站錯層了——那段邏輯該待在 gbind，core 只回傳純資料。

心智模型

兩套平行回合系統

同一顆 core 裡有兩個平行互不干涉的場景。回合驅動各自獨立，不共用不依賴。改東西前先確認自己在哪個模組。

⌘

地城探索

src/core/turn/ — TurnEngine，最傳統回合制：actor list 依加入序、撞擊即攻擊、下第 5 層通關。橋樑：ZoneWorld。

◈

戰棋戰鬥

src/core/tactics/ — ActionBar/Battle，ToME4 行動值模型：kCtToAct=1000，溢出保留。橋樑：TacticsBattle。

真相層

檔案回答什麼
CODE_MAP.md（workflows/common/code-map/）東西在哪，「改 X 去哪」的第一站
turn_engine.h / apply_action.cpp地城回合地基：actor list、step、撞擊攻擊、decide_npc
tactics/battle.h戰棋子回合狀態機
