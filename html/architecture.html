大圖

它在整個 gamecore 的哪一層

gamecore 規畫成三層，由大到小。這個 repo 只做最底層——區域層（Area Layer），也就是「你實際站在一張地圖上戰鬥」的那一層。

gamecore 三層架構
World Layer 世界／全域時間、大地圖 │ Region Layer 區域群、跨地圖移動 │ Area Layer ◀── 本 repo（gamecore-zone） 一張地圖 · ECS · FOV · 回合排程 · 戰鬥
出身 本層是從 opennefia-cpp hard fork 出來的：保留了成熟的 ECS／FOV／戰鬥骨架， 但把 OpenNefia 特有的機制（事件匯流排、原型管理器、spawn 系統）整套拿掉，換上自己的回合排程與效果系統。

資料怎麼流

一次玩家輸入發生了什麼

前端永遠不直接改世界，只「提交指令」與「推進時間」，規則全在 C++。

一次「按 D 往右走」的資料流
[GDScript] map_view.gd 按下 D │ world.submit_hero_move(1, 0) # 只登記指令，不馬上動 ▼ [GDExtension] zone_world_gd.cpp 把指令塞進英雄的 OngoingAction │ Timer 每 0.2s → world.step_scheduler() ▼ [C++ core] energy_channel_scheduler.cpp 發能量 → 輪到英雄 → on_resolve │ zone_effects: resolve_move(1,0) ▼ 撞牆？攻擊？拾取？ → 發 ZoneEvent + trace │ 推進到「英雄再次等指令」才停 ▼ [GDScript] drain_events → 重畫地圖 + 更新 debug 面板
關鍵設計 C++ 擁有規則、擁有時間；Godot 只負責「畫面 + 輸入 + 計時器」。 三條時鐘是分開的：render_frame（畫）、on_input（提交）、advance_tick（推進）。 世界阻塞的定義 = 英雄 idle 且沒指令，此時 C++ 不空轉，靜靜等你下一步。
