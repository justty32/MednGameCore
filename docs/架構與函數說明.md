# 架構與函數說明

> 最後更新：2026-07-19

## 三層鳥瞰

```
玩家按鍵 (Godot)
    │
    ▼
projects/godot_zone/       (GDScript)    — 畫面、輸入、HUD
    │  player_move / player_wait / next_round
    ▼
projects/core/src/gbind/   (GDExtension) — 唯一認識 Godot 的橋樑
    │  ZoneWorld（地城）、TacticsBattle（戰棋）
    ▼
projects/core/src/core/    (純 C++/EnTT) — godot-free，可單元測試
    │  turn/（地城回合）、tactics/（戰棋）、
    │  components/、systems/、maps/、serialize/
```

**鐵律**：`projects/core/src/core/` 完全 godot-free（不可 `#include <godot_cpp/...>`）。`projects/core/src/gbind/` 是唯一認識 Godot 的橋樑層。

## 地城探索（TurnEngine）

### 一回合的資料流

玩家按一鍵 → 英雄走一步 → 全 NPC 各動一次：

1. `map_view.gd` 收到按鍵 → `ZoneWorld::player_move(dx, dy)`
2. 此指令被 `submit()` 給 `TurnEngine` 裡等待的玩家 actor
3. `ZoneWorld::pump()` 反覆 `engine_.step()`：
   - 玩家 actor → 用投遞的指令 `resolve()`（最終 `apply_action`）
   - NPC → `decide_npc()` 決策 → `resolve()` → `apply_action`
4. `apply_action` 改動世界，產出 `ZoneEvent`
5. `ZoneWorld::drain_events()` → Godot signal
6. 全部 actor 跑完 → `RoundDone`，發 `round_finished`

### TurnEngine（turn_engine.{h,cpp}）

內部是一條 `std::list<entt::entity>`（順序＝加入序，hero 最先）。

| 函數 | 作用 |
|------|------|
| `add_actor(e)` | 新 actor 接到清單尾端（重複略過） |
| `remove_actor(e)` | 從清單移除死亡/離場 actor，cursor 前移防懸空 |
| `begin_round()` | cursor 回到清單頭 |
| `step(ctx)` | 推進一個 actor。回傳 `Acted`(可續跑) / `WaitingPlayer`(等玩家指令) / `RoundDone`(整輪跑完)。首次輪到該 actor 時 `ActPointComponent` 設 1000，動完歸 0 |
| `submit(e, a)` | 玩家投遞指令 |
| `waiting_actor()` | 目前卡在哪個 actor |

`EngineCtx`：傳給 `step()` 的依賴包（registry + decide/resolve/trace 三個 callback），引擎不持有 registry。

### apply_action（apply_action.{h,cpp}）

把 `Action{Idle, Move, Wait}` 落地到世界。**沒有獨立攻擊動作**——撞 actor 就是攻擊。

| 情況 | 結果 | 事件 |
|------|------|------|
| Move → 撞牆/出界 | 停住 | `BumpedWall` |
| Move → 撞 actor（致死） | 扣 `CombatStatsComponent.attack` 傷害 | `ActorDied` |
| Move → 撞 actor（未死） | 扣傷害 | `BumpedActor` |
| Move → 空格（踩道具） | 移動，自動拾取 health_potion | `ItemPickedUp` |
| Move → 下樓梯 | 移動，觸發下樓 | `ReachedStairDown` |
| Wait / Idle | 消耗回合 | — |

`actor_at(reg, x, y, except)`：查 `(x,y)` 站著哪個 actor（公開在標頭，撞擊判定與 NPC 尋路避讓共用）。

**死亡不在此 destroy**：只發事件，由呼叫端（ZoneWorld）統一移除。

### decide_npc（npc_ai.{h,cpp}）

純決策函式，回傳 `Action`，唯一的副作用是更新 `NpcAiComponent` 的警覺狀態。

`decide_npc(reg, map, self, target, rng, cfg)`，`cfg: { sight_radius=10, alert_memory=6 }`

決策順序：
1. **更新警覺**：LOS + `sight_radius` 內看得到目標 → 警覺；否則 `alert_turns` 逐回合遞減，到期解除
2. **已警覺且相鄰** → 朝目標 Move（撞擊攻擊）。**不受 `move_chance` 閘門**。
3. **擲 `move_chance` 不過** → Wait
4. **已警覺 → 追擊**：大 delta 軸優先，受阻換另一軸；兩軸都不可走則徘徊
5. **未警覺 → 徘徊**：隨機四方向

永遠避開牆與其他 actor。

### 元件（components/）

| 元件 | 用途 |
|------|------|
| `ActorComponent` | tag，標記有行動資格 |
| `ControllerComponent` | Player / Self / Faction |
| `ActPointComponent` | 行動點數，每回合重設 1000、動完歸 0 |
| `HeroComponent` | tag，唯一辨識英雄 |
| `SpatialComponent` | `x,y` + parent |
| `HealthComponent` | `hp / max_hp` |
| `CombatStatsComponent` | `attack`、`move_chance` |
| `NpcAiComponent` | `alerted`、`alert_turns` |
| `ItemComponent` | 道具 type/value |
| `WorldStateComponent` | `turn_count`、`current_floor` |

### FOV（systems/fov_system.*）

- `compute_fov(map, ox, oy, radius)`：Bresenham 射線算視野，更新 `visible` + `explored`
- `los(map, x0, y0, x1, y1)`：兩點間視線檢查（供 `decide_npc` 判斷能否看到目標）

### 地圖（maps/）

- `tile.h`：`Tile{terrain, flags}`（可走/擋視線/下樓梯）
- `map_data.h`：`MapData`（稠密 tile 網格，列優先）
- `map_gen.{h,cpp}`：BSP 地下城生成（房間+走廊）

### ECS 底層（ecs/）

- `EntityManager`：`entt::registry` 薄封裝，`create/destroy/emplace/get` 等

### 序列化（serialize/）

- `all_components.h`：**所有要存檔的元件清單**（唯一真相來源，新增元件必改此檔）
- `save_load.h`：`save()` / `load()`（stream / 檔案路徑 / SaveStore 三層）

## ZoneWorld（projects/core/src/gbind/zone_world_gd.*）

唯一認識 Godot 的橋樑類別。對 GDScript 暴露：

| 方法 | 作用 |
|------|------|
| `next_round()` | 新一輪，推進到「等玩家指令」或「回合結束」 |
| `player_move(dx, dy)` | 投遞玩家移動指令 |
| `player_wait()` | 等待 |
| `is_waiting_player()` | 是否卡在等玩家 |
| `get_tile_flags()` | 整張地圖旗標（PackedByteArray，bit0 可走/bit1 下樓梯/bit2 可見/bit3 曾探索） |
| `get_visible_entities()` | Array[Dictionary]：`{x,y,kind,hp,max_hp}`，只含視野內實體 |
| `restart()` | 重開（若曾 `set_seed()` 則沿用 seed） |
| `set_seed(seed)` / `get_seed()` | 固定種子（地圖生成+ NPC AI 都吃同一顆） |
| `save_game/load_game/has_save_game(path)` | 存讀檔 |

**內部關鍵**：

| 方法 | 作用 |
|------|------|
| `pump()` | 反覆 step，遇等待/回合結束/換層停 |
| `drain_events()` | ZoneEvent → Godot signal |
| `next_floor()` | 下樓成長（`+HERO_MAXHP_PER_FLOOR/+HERO_HEAL_PER_FLOOR/+HERO_ATK_PER_FLOOR`）+ 重建樓層 |
| `setup_world()` / `setup_map()` | 開局生成 |

**Signal**：`world_changed` / `round_finished` / `floor_changed` / `hero_grew` / `hero_bumped_wall` / `hero_attacked` / `hero_hurt` / `npc_died` / `item_picked_up` / `game_over` / `game_won`

## 前端（projects/godot_zone/）

- `map_view.tscn` + `map_view.gd`：主場景，收按鍵、叫 ZoneWorld、接 signal 更新 HUD/訊息列
- `dungeon_view.gd`：**唯一決定 tile 與顏色**的地方。從 `assets/tilesheet.png`（Kenney 1-Bit，CC0）取圖塊
- `tile_atlas.gd`：兩場景共用的圖塊座標（唯一真相來源）
- `verify.gd`：headless 端到端驗證，BFS 機器人殺向樓梯，斷言必達結局

## SRPG 戰棋（projects/core/src/core/tactics/）+ TacticsBattle

與地城**平行獨立**：共用 ECS/MapData/頻繁 component/序列化基建，但回合驅動另寫一套。**不共用、不依賴** TurnEngine/Action/apply_action。

### ActionBar（action_bar.{h,cpp}）

ToME4 行動值模型：`kCtToAct=1000`。

| 方法 | 作用 |
|------|------|
| `advance(reg)` | 每個單位 `ct += speed`，有 `ct >= 1000` 者出手；同時達標取 ct 高者，平手取加入序在前者 |
| `consume(reg, e)` | `ct -= 1000`，**不歸零**（溢出保留，快角可連動兩次） |
| `forecast(reg, n)` | 在複本上模擬 n 步，不碰真實 ct |

### 可達集（move_range.{h,cpp}）

- `compute_move_field(reg, map, self)`：四方向 BFS（每步固定成本 1），牆+其他單位佔格**不可通行**
- `reachable_tiles(f)`：可取格（含起點）
- `path_to(f, tx, ty)`：沿 dist 遞減回溯路徑（只給前端動畫用，核心結算是瞬移）

### apply_tactics_action（apply_tactics_action.{h,cpp}）

**只驗證幾何合法性**（可達/射程/敵隊），不管子狀態（那是 Battle 的事）。

| 指令 | 驗證 | 事件 |
|------|------|------|
| `MoveTo(dst)` | dst 在可達集內 | `Moved` / `Rejected` |
| `Attack(target)` | 在 `attack_range` 內且敵隊 | `Attacked` + `UnitDied` |
| `Wait` | — | — |

### decide_tactics（tactics_ai.{h,cpp}）

純函式。排序鍵依序：
1. **deficit** = `max(離最近敵人距離 - attack_range, 0)`——越小越好（能不能打到）
2. **nearest** = 到最近敵人距離——**越大越好**（關鍵：進射程就別再靠近，否則遠程送死）
3. **steps**——越小越好

### Battle（battle.{h,cpp}）

單位回合子狀態機：

```
移動一次（可選）→ 行動一次（攻擊/Wait）
規則：可「移動後攻擊」，不可「攻擊後再移動」。攻擊即結束回合。
```

| 方法 | 作用 |
|------|------|
| `begin_next_turn(reg)` | 行動條選出下個出手者；已分勝負回 null |
| `command(reg, map, a, events)` | 子狀態閘門（moved/acted 檢查）+ 呼叫 apply_tactics_action |
| `run_ai_turn(reg, map, events)` | AI 打完一整個回合（最多 3 步防卡死） |
| `winner(reg)` | 清點存活數，殲滅方勝。僅支援兩隊 |

### TacticsBattle（tactics_battle_gd.*）

與 ZoneWorld 平行，自建 20×14 競技場。**不在 `_ready()` 自動開局**——`pump()` 會跑 AI 並發 signal，前端需先接信號。

**方法**：`start_battle(seed)` / `command_move(x,y)` / `command_attack(id)` / `command_wait()` / `get_units()` / `get_turn_order(n)` / `get_move_tiles()` / `get_attack_targets()` / `get_winner()`

**Signal**：`turn_started` / `unit_moved` / `unit_attacked` / `unit_died` / `battle_over`

### 測試（test_tactics.cpp，22 case）
