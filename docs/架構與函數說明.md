> 最後更新：2026-06-21

## 1. 三層鳥瞰：誰呼叫誰

```
   玩家按鍵 (Godot)
        │
        ▼
 ┌─────────────────────┐   godot_zone/  (GDScript：畫面、按鍵)
 │  map_view.gd        │   按一鍵 → 呼叫 ZoneWorld 的方法
 └─────────┬───────────┘
           │  player_move / player_wait / next_round
           ▼
 ┌─────────────────────┐   src/gbind/  (C++ ↔ Godot 橋樑)
 │  ZoneWorld          │   把 Godot 呼叫翻譯成核心邏輯；事件翻成 Godot signal
 └─────────┬───────────┘
           │  使用
           ▼
 ┌─────────────────────┐   src/core/  (純 C++，不認識 Godot)
 │  TurnEngine         │   回合排程
 │  apply_action       │   把動作結算到世界
 │  ECS / 元件 / 系統   │   資料與規則
 └─────────────────────┘
```

**重點原則**：`src/core/` 完全不依賴 Godot（純邏輯、可單元測試）；只有 `src/gbind/` 認識 Godot。

## 2. 一回合裡發生什麼（資料流）

玩家按一下方向鍵，整條鏈是這樣跑的：

1. `map_view.gd` 收到按鍵 → 呼叫 `ZoneWorld::player_move(dx, dy)`。
2. `ZoneWorld` 把這個指令 `submit()` 給 `TurnEngine` 裡正在等待的玩家 actor。
3. `ZoneWorld::pump()` 反覆呼叫 `engine_.step()`：
   - 玩家 actor → 用剛投遞的指令 `resolve()`（最終呼叫 `apply_action`）。
   - 每個 NPC → `decide()` 決策（`decide_chase`）→ `resolve()` → `apply_action`。
4. `apply_action` 改動世界（移動/攻擊/撿道具…），把發生的事丟進 `events_`。
5. `ZoneWorld::drain_events()` 把事件翻成 Godot signal，前端據此更新畫面。
6. 一輪所有 actor 跑完 → `RoundDone`，發 `round_finished` signal。

**回合制的精髓**：按一鍵 ＝ 英雄走一步 ＋ 全部 NPC 各動一次。

## 3. 核心層 `src/core/`

### 3.1 回合引擎 `turn/`

#### `turn_engine.{h,cpp}` — `TurnEngine`
回合排程的心臟。內部就是一條 actor 的 `std::list`（順序＝加入順序，hero 最先）。

| 函數 | 做什麼 |
|------|--------|
| `add_actor(e)` | 新 actor 出現 → 接到清單尾端（重複則略過）。 |
| `remove_actor(e)` | 死亡/離場 → 從清單移除；若剛好輪到它，cursor 安全前移避免懸空。 |
| `contains(e)` / `size()` / `order()` | 查詢清單。 |
| `clear()` | 清空整條清單與狀態。 |
| `begin_round()` | 開新一輪：cursor 回到清單頭。 |
| `step(ctx)` | **核心**：推進一個 actor。回傳 `Acted`（動完可再 step）/ `WaitingPlayer`（卡在玩家等指令）/ `RoundDone`（整輪跑完）。每個 actor 首次輪到時把 `ActPointComponent` 設 1000，動完歸 0。 |
| `submit(e, a)` | 玩家把指令投遞進來（存進 `pending_`）。 |
| `waiting_actor()` | 目前卡在哪個 actor 等指令。 |

> `EngineCtx`：傳給 `step()` 的依賴包（`registry` ＋ `decide`/`resolve`/`trace` 三個 callback）。引擎本身不持有 registry，保持純粹好測試。

#### `action.h` — `Action`
一個「指令」的值型別，玩家和 NPC 共用。只有三種：`Idle` / `Move` / `Wait`。
**沒有獨立攻擊動作**——攻擊＝移動進入有 actor 的格子。
- `Action::idle()` / `wait()` / `move(dir)` — 建構各種動作。

#### `apply_action.{h,cpp}` — 動作結算
把一個 `Action` 真正落地到世界上。

| 函數 | 做什麼 |
|------|--------|
| `apply_action(reg, map, self, a, events)` | 結算一個動作：撞牆（發 `BumpedWall`）/ 撞 actor（攻擊，發 `BumpedActor` 或 `ActorDied`）/ 移動（順帶自動撿道具、踩到下樓梯發 `ReachedStairDown`）。死亡目標只發事件、不在這裡 destroy（交呼叫端統一移除，避免迭代失效）。 |
| `decide_chase(reg, self, target)` | 最精簡 NPC AI：朝目標移動一格（相鄰即撞擊攻擊）；無目標則 `Wait`。**這是回合引擎實際用的 NPC 決策。** |
| `actor_at(...)`（內部） | 查某格上站著哪個別的 actor（撞擊判定用）。 |

#### `zone_event.h` — `ZoneEvent`
核心層發出的遊戲事件（核心不認識 Godot，只丟事件）。種類：`BumpedWall` / `BumpedActor` / `ActorDied` / `ItemPickedUp` / `ReachedStairDown`。

#### `move_dir.h` — 方向編碼
- `encode_dir(dx, dy)` / `decode_dir(p, dx, dy)` — 把 8 方向 `(dx,dy)` 壓成一個 0..8 整數（存在 `Action.param`）來回轉換。

### 3.2 元件 `components/`（ECS 的「資料」）

| 元件 | 內容 / 用途 |
|------|-------------|
| `ActorComponent` | 空 tag，標記「有行動資格」（英雄、NPC）。物品/地形不掛。 |
| `ControllerComponent` | 這個 actor 由誰操控：`Player`（暫停等玩家）/ `Self`（AI 決策）/ `Faction`（軍團，未實作，暫等同 Self）。 |
| `ActPointComponent` | 行動點數，每回合重設 1000、動完歸 0。為未來「依成本多次行動」預留。 |
| `HeroComponent` | 空 tag，正向標記唯一辨識英雄（取代脆弱的排除法）。 |
| `SpatialComponent` | 座標 `x,y` ＋ `parent`（場景圖父子；目前多為頂層）。 |
| `HealthComponent` | `hp` / `max_hp`，預設 10/10。 |
| `CombatStatsComponent` | `attack`（攻擊力，預設 2）、`move_chance`（移動機率）。 |
| `NpcAiComponent` | NPC AI 狀態：`alerted`（是否發現英雄）、`alert_turns`（失去視線後追幾回合）、`is_caster`（註：技能已移除，此欄為歷史殘留）。 |
| `ItemComponent` | 道具：`type`（目前只有 `health_potion`）、`value`（回血量）。 |
| `WorldStateComponent` | 全域狀態：`turn_count`（回合數）、`current_floor`（樓層）。掛在地圖實體上，隨存檔一起存。 |

### 3.3 系統 `systems/`（ECS 的「規則」）

#### `fov_system.{h,cpp}` — 視野
- `compute_fov(map, ox, oy, radius)` — 用 Bresenham 射線算英雄視野，更新 `visible`（本回合）＋ `explored`（霧中戰爭）。
- `los(map, x0,y0, x1,y1)` — 兩點間視線檢查（NPC AI 判斷能否看到英雄用），不改地圖狀態。

#### `npc_ai_system.{h,cpp}` — 群體 NPC AI（注意：另一套）
- `npc_ai_system(reg, ctx)` — 一次處理「所有」NPC 的視野警覺、貼身攻擊、追蹤、徘徊。用固定種子 RNG（可重現）。
- ⚠️ **這是和 `decide_chase` 平行存在的另一套 AI**（更完整：含警覺/失憶/徘徊）。回合引擎走的是 `decide_chase`；這支是否仍接在主迴圈上值得確認，可能是重構後的待整併殘留。

### 3.4 地圖 `maps/`

| 檔案 | 內容 |
|------|------|
| `tile.h` — `Tile` | 單格：`terrain` id ＋ `flags`（可走/擋視線/下樓梯）。提供 `is_walkable()` 等查詢。 |
| `map_data.h` — `MapData` | 整張地圖（稠密 tile 網格，列優先索引）。一張地圖是一個元件掛在「地圖實體」上，不是每格一個實體。提供 `at()` / `in_bounds()` / FOV 可見性查詢；`tiles` 存檔、`visible/explored` 不存（load 後重置）。 |
| `map_gen.{h,cpp}` | `generate_bsp_dungeon(map, rng)` — BSP 地下城生成：整張填牆，再挖房間＋走廊，回傳房間清單（第 0 間＝英雄起始房）。 |

### 3.5 ECS 底層 `ecs/`

- `entity_manager.h` — `EntityManager`：`entt::registry` 的薄封裝。`create/destroy/valid`、`emplace/get/try_get/has/remove` 元件、`add_system/tick` 跑系統。複雜查詢直接 `registry()`。
- `system_ctx.h` — `SystemCtx`：傳給每個系統的依賴包，目前是空佔位（未來放 rng、locale 等）。

### 3.6 序列化 `serialize/`（存讀檔）

- `all_components.h` — `AllComponents`：所有「要存檔的元件」清單（**唯一真相來源**）。加新元件要存檔就改這裡。
- `save_load.h` — `save()` / `load()`：把整個 registry 與 bytes/檔案/SaveStore 來回轉換。三層 API（stream / 檔案路徑 / SaveStore）。
- `entt_cereal_archive.h` / `save_store.h` — cereal 與 EnTT snapshot 的轉接、儲存後端介面。

## 4. 橋樑層 `src/gbind/` — `ZoneWorld`

唯一認識 Godot 的地方。對 GDScript 暴露的 Node，內部持有 `EntityManager em_` ＋ `TurnEngine engine_`。

**對前端公開的方法**（GDScript 可直接呼叫）：

| 方法 | 做什麼 |
|------|--------|
| `next_round()` | 「下一回合」：開新一輪並推進到「玩家要等指令」或「回合結束」。 |
| `player_move(dx, dy)` | 玩家移動指令；投遞給等待中的玩家 actor 並續跑該回合。 |
| `player_wait()` | 玩家原地等待。 |
| `is_waiting_player()` | 現在是否卡在玩家 actor 等指令。 |
| `round_in_progress()` | 這回合還沒跑完？ |
| `get_map_width/height()`、`is_walkable()`、`generate_map_image()` | 地圖查詢與渲染圖。 |
| `get_hero_x/y`、`get_hero_hp/max_hp`、`get_turn_count`、`get_npc_count`、`get_current_floor` | 狀態查詢（給 HUD）。 |
| `restart()` | 重開一局。 |
| `save_game/load_game/has_save_game(path)` | 存讀檔。 |
| `get_debug_text/log()`、`set/get_trace_enabled()`、`clear_debug_log()` | debug 用。 |

**內部關鍵函數**（private）：

| 函數 | 做什麼 |
|------|--------|
| `setup_world()` / `setup_map()` | 開局：生成地圖、放英雄與 NPC、註冊進引擎。 |
| `make_ctx()` | 組出 `EngineCtx`（綁好 decide/resolve/trace callback）給 `step()` 用。 |
| `pump()` | **驅動回合**：反覆 `step()`，遇玩家等待/回合結束/換樓層就停。 |
| `drain_events()` | 把 `events_` 翻成 Godot signal；回傳「英雄是否踩到下樓梯」。 |
| `npc_decide(e)` | NPC 決策入口（接 `decide_chase`）。 |
| `next_floor()` | 換下一層。 |
| `recompute_fov()` | 重算英雄視野。 |
| `add_actor_to_engine(e)` | 把實體加進回合引擎。 |

## 7. 一句話記住每層

- **core**：規則與資料，純 C++，可單測。
- **gbind / ZoneWorld**：翻譯官，唯一碰 Godot 的地方。
- **godot_zone**：畫面與輸入。
- **TurnEngine + apply_action**：回合制的兩個主角——一個管「輪到誰」，一個管「動作的結果」。
