# 架構演進總覽（索引）

> 日期：2026-06-11
> 一句話定位：gamecore-zone 從「實驗沙盒」走向「三層架構正式區域層」的工程演進路線圖索引。

---

## 現況一句話

純 core（`src/core/`，zone_core STATIC、godot-free）已有：三種可切換回合排程器
（`src/core/turn/`）、ActionDef+ActionLibrary JSON 載入、TurnWorld 抽象（on_actor_turn
hook + trace sink）、ZoneEvent 事件、DoT、NPC 追擊腦；GDExtension 端 `ZoneWorld`
（`src/gbind/zone_world_gd.cpp`，763 行）把這些接到 Godot 4.6。ctest 49 案全綠、
headless VERIFY PASSED。**但**：多角色 order 表模型尚未落地、save/load 不含排程器
狀態、前端資料介面仍是字串 dump、ZoneWorld 已成 god class。

## 建議推進順序（相依關係）

```
07 技術債 P0 項（序列化缺口）─┐
01 排程器收斂（定 B 為主幹）──┼─→ 02 order 表落地 ─→ 04 snapshot 介面 ─→ 05 跨層整合
03 職責邊界（ZoneWorld 拆分）─┘                          06 建置（隨時可做，獨立）
```

理由：02（order 表）會改 `TurnScheduler` 介面與 `waiting_actor` 語意，01 先收斂
可少改兩份排程器；03 的 ZoneWorld 拆分讓 04 的 snapshot 層有乾淨落點；05 依賴
04 的結構化介面才談得上跨層資料交換。

## 全域風險備忘

- **實驗期慣性**：目前一切「additive、不動既有路徑」（如 `move()` 舊路徑與
  scheduler 新路徑並存於 `zone_world_gd.h`）。實驗期合理，但收斂期要敢刪，
  否則每個新功能都要 ×2（雙路徑）或 ×3（三排程器）維護。
- **未 commit 的工作量**：session_log 多次標注「未 commit」。演進前先把現況
  commit 成基線，否則收斂重構無法 bisect。
- **單人專案的文件腐化**：spec §7 已經歷一次「單 hero 作廢→callout 修補」；
  收斂後應把作廢內容歸檔而非繼續疊 callout。
