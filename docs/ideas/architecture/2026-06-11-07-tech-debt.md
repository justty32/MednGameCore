# 技術債盤點

> 日期：2026-06-11
> 定位：把目前 gamecore-zone 的已知債務列成可排序清單，避免它們在玩法擴張後變成隱形地雷。

---

## P0：會造成錯誤狀態或假通過

### 1. 序列化缺元件

`AllComponents` 未納入排程器時代新增的 Energy、OngoingAction、TimedEffects、PlayerControlled。
結果是存檔讀回後能量、詠唱、DoT、玩家阻塞語意都可能遺失。

處理方向見 `docs/ideas/quality/01-test-coverage.md`。

### 2. verify.gd 仍有 print-only 檢查

只印不斷言會造成「流程跑完但世界沒變」的假通過。所有 verify case 應至少斷言：

- 世界 clock / turn count 改變。
- actor 位置、HP、事件數、狀態之一符合預期。
- save/load 後至少一個非平凡 component round-trip。

### 3. scheduler safety guard 靜默返回

guard 耗盡時若不 trace / 不回報，會讓壞 config 看起來像 idle。應回報 `scheduler stalled` 事件或 trace。

## P1：會放大後續維護成本

### 4. `ZoneWorld` god class

`zone_world_gd.cpp` 同時負責 mapgen、spawn、ActionLibrary、scheduler、debug、save/load、Godot binding。
短期可接受，下一步應抽：

- `ZoneSession`：持有 TurnWorld、scheduler、action library。
- `ZoneSpawner`：map + prototype → actor。
- `ZoneBindingAdapter`：C++ 結構轉 Godot Dictionary。

### 5. 雙路徑行為並存

舊 `move()` 路徑與 scheduler 路徑若長期並存，任何戰鬥機制都要補兩份。
建議等 scheduler path 穩定後，把舊路徑降為測試 helper 或刪除。

### 6. Action.def 使用整數索引

存檔或 ongoing action 若保存 def index，actions.json 重排就會指錯技能。短期鎖 JSON 順序，長期加穩定 `id`。

## P2：可改善但不阻塞

- trace 字串混合中文、人類訊息、debug token，未來若要 localization / structured log 需分層。
- `eid` / entity id 在 debug 輸出中可讀性差，應有穩定 display id 或 actor label。
- mapgen / turn RNG / NPC AI 種子策略不一致，會阻礙重播與差分測試。

## 建議處理順序

1. 補序列化元件與 round-trip 測試。
2. 改 verify.gd 斷言準則。
3. scheduler stalled 可觀測。
4. 抽 `ZoneSession`，讓 snapshot / event export 有乾淨落點。
5. ActionDef 穩定 id。

## 不做的事

- 不為了「漂亮」重構 core；每個債務項都要對應錯誤風險或後續功能阻塞。
- 不一次砍掉所有 debug 字串；先有結構化替代，再移除依賴。
