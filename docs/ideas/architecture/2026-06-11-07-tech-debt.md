## P0：會造成錯誤狀態或假通過

### 1. verify.gd 假通過教訓（仍有效）

只印不斷言會造成「流程跑完但世界沒變」的假通過（session_log 2026-06-10 曾踩）。所有 verify
case 應至少斷言：

- turn count／回合進度改變。
- actor 位置、HP、事件數之一符合預期。
- save/load 後至少一個非平凡 component round-trip。

現況 verify.gd 已改用新 API（player_wait 推進、player_move 四方移動、NPC 追擊致 HP 下降、
trace、存讀檔 round-trip）並 VERIFY PASSED；此項作為**長期紀律**保留：新增 verify case 一律
先寫會失敗的斷言再接通。

### 2. 序列化 round-trip 缺結構性測試（仍有效）

雖然「漏登記」的具體事故已隨重構消失，但**根因防護仍缺**：沒有「save→load→再 save，bytes
相等」的常設測試。新增 component（如未來能量擴充）仍可能忘記登記 `all_components.h` type_list。
應補此測試 + `static_assert` 防呆（見 03）。

## P1：會放大後續維護成本

### 3. `ZoneWorld` god class（仍有效，最大項）

`zone_world_gd.cpp` 同時負責 mapgen、spawn、TurnEngine 宿主、event→signal、trace、debug 字串、
save/load、Godot binding。短期可接受，下一步應抽（見 03）：

- `ZoneSession`：持有 EntityManager + TurnEngine + events + 生命週期（純 core 可測）。
- `ZoneSpawner`：map + prototype → actor。
- `ZoneBindingAdapter`：C++ 結構轉 Godot Dictionary（與 04 snapshot 合做）。

### 4. eid / entity id 對外不穩定（仍有效）

entity id 在 debug 輸出與未來 snapshot/事件流中可讀性差、且 entt eid 含 version 位，直接外露
給前端不可靠（02 的 `submit_actor(actor_id)` 與 04 的 `actors[].id` 都需要穩定 display id）。
應在 ZoneSession/binding 層做穩定編號映射，而非把原始 eid 丟給 Godot。

## P2：可改善但不阻塞

- trace 字串混合中文、人類訊息、debug token，未來若要 localization / structured log 需分層。
- mapgen / turn RNG / NPC AI 種子策略不一致，會阻礙重播與差分測試（02 的取人策略切換與決定性
  尤其依賴此）。

## 新增（重構後浮現）

### 5. `godot_zone/bin/.so` 需與 build 同步（已用 post-build 解決）

`godot_zone/bin/` 已 gitignore，Godot 端讀取的 `.so` 不在版控。曾因手動忘記複製新二進位而
除錯到舊行為。**現已由 `zone_gd` 的 POST_BUILD `copy_if_different` 自動同步**（見 06 §2），
此項視為已緩解；保留記錄以免未來改動 build 時退化。

## 建議處理順序

1. 補序列化 round-trip 測試 + static_assert 防呆。
2. 維持 verify.gd「先寫失敗斷言」紀律。
3. 抽 `ZoneSession`，讓 snapshot / event export 有乾淨落點。
4. 建立穩定 display id 映射（02/04 前置）。

## 不做的事

- 不為了「漂亮」重構 core；每個債務項都要對應錯誤風險或後續功能阻塞。
- 不一次砍掉所有 debug 字串；先有結構化替代（04 snapshot），再移除依賴。
