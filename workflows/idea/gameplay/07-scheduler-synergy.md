# 能量/先攻擴充 × Gameplay 機制相性

> 日期：2026-06-11（設計內容）
> 狀態更新：2026-06-21
> 定位：盤點若未來引入「能量/速度/詠唱（channel）」時間擴充，哪些玩法會因此更有趣。
>
> **前提已不適用現況（2026-06-21）**：原先的三種可切換排程器
> （A 能量瞬發 / B 能量+channel / C 純 tick）已於回合系統重構中**整體移除**，
> 回到最傳統回合制 `TurnEngine`（actor 順序串列、每人每回合行動一次）。
> 本檔保留的設計價值，重新定位為**「若未來在 TurnEngine 之上再引入能量/先攻擴充時，
> 各玩法機制的可能性」**——以下 A/B/C 三模型請讀作「三種可選的時間語法擴充方向」，
> 而非現有程式。`ActPointComponent`（現重設為 1000、行動後歸 0）是
> 「未來依成本行動多次」的預留欄位，是這類擴充的潛在地基。

---

## 1. 三種時間擴充方向簡述（未來可選，皆未實作）

| 方向 | 體感 |
|---|---|
| A 能量瞬發 | 快慢差、誰先動、行動立即結算 |
| B 能量 + channel | 詠唱、打斷、風險窗口 |
| C tick remaining | 固定倒數、DoT 與延遲效果清楚 |

## 2. 機制相性矩陣（在各時間擴充方向下）

| 機制 | A | B | C | 備註 |
|---|---|---|---|---|
| 命中/暴擊 | 高 | 高 | 高 | 與 scheduler 幾乎獨立 |
| cooldown | 高 | 高 | 中 | B 下 cd + 詠唱形成雙節奏 |
| channel spell | 低 | 最高 | 高 | A 可視為 weight 動作，不是主舞台 |
| interrupt | 中 | 最高 | 高 | B 最有戲 |
| DoT | 中 | 高 | 最高 | C 的 tick 感最直觀 |
| 防禦/Guard | 高 | 高 | 中 | B 可用來中斷施法改防禦 |
| 速度 buff | 最高 | 高 | 高 | A 最容易感知 |

## 3. 設計原則（若引入時間擴充）

- **基準是最簡 TurnEngine**：任何時間擴充都應是可選層，不引入時遊戲仍完整可玩。
  （上一輪正因三排程器並存、過度服務時間模型而被整體移除——這是核心教訓。）
- 若機制強依賴某方向（如 B 的 channel interrupt），其餘方向至少要有退化語意，
  或在最簡 TurnEngine 下有合理的對應（如打斷退化為「本回合不行動」）。
- trace（`EngineCtx.trace`）要標明相關原因，例如 cooldown、channel interrupted、not ready。

## 4. 內容建議

- A 方向主打：速度、連擊、短 cd、閃避。
- B 方向主打：高風險法術、打斷、防禦反應。
- C 方向主打：陷阱、DoT、倒數爆炸、延遲召喚。

同一技能可依時間語法有不同手感，但資料定義應盡量共用。

## 5. 不做的事

- 不為每個時間方向寫一套完全不同技能表。
- 若真的引入多種時間語法，不把它當難度選項；它們是時間語法，不只是快慢。
- **不在收斂前同時並存多套時間模型**——這正是上一輪實驗被整體移除的原因；
  若要引入，先選定一種收斂方向，疊在 TurnEngine 之上。
