# CI 構想

> 日期：2026-06-21
> 定位：用最小成本建立回歸護欄，先保 core，再接 Godot headless。
>
> **狀態更新（2026-06-21）**：構想大致不變；新增**並行限制鐵則**（OOM 教訓）、改用 doctest 二進位直跑，
> 並補上 GDExtension 的 post-build `.so` 複製與 import 前置。

---

## 0. 鐵則：建置務必限制並行（OOM 教訓）

**所有 CI 建置一律帶 `-j` 上限（如 `-j4`）。** 曾因無上限 `-j` 同時數百個編譯程序耗盡
RAM 觸發 OOM 強制重啟。CI runner 記憶體通常比本機更小，更不可放任無上限並行——
這是 CI 設定的第一條，不可省略。

## 1. 第一階段：core doctest（優先序：高）

GitHub Actions job：

```text
checkout
configure cmake
build zone_test          # cmake --build build --target zone_test -j4   ← 限制並行
run zone_test            # 直接跑 doctest 二進位（--output-on-failure 等同其內建報告）
```

先跑 Ubuntu。Windows / macOS 等專案穩定後再補。
判定：doctest 全綠（現況 29 cases / 93 assertions）。

## 2. 快取

cache key 包含：

- compiler
- CMakeLists hash
- dependency lock / godot-cpp commit

doctest 這類小依賴快取價值低，不必過度設計；godot-cpp 編譯較重，值得快取。

## 3. 第二階段：Godot headless（中）

難點是取得固定 Godot binary 與建置 GDExtension。流程：

- 使用官方 Godot 4.6 mono release zip（鎖版）；可 cache binary。
- `build zone_gd -j4`（**限制並行**）——POST_BUILD 會把 `libzone_gd.so` 複製到 `godot_zone/bin/`
  （該目錄 gitignore，故 CI 上必須靠這步產生 `.so`，不能假設已存在）。
- `godot-mono --headless --path godot_zone --import`（建立 `.godot/extension_list.cfg`）。
- `godot-mono --headless --path godot_zone -s res://verify.gd`，以 `VERIFY PASSED` 字串判定
  （結尾 editor core dump 為已知無害，勿用 exit code 當唯一判據）。
- 上傳 log。

這個 job 可先設 manual 或 nightly，避免每次 push 都太慢。

## 4. PR 檢查分層

- 必跑：build（`-j4`）/ doctest。
- 可選：headless verify。
- 夜間：simulation 多 seed、benchmark。

## 5. 不做的事

- 不一開始就追求全平台矩陣。
- 不讓 CI 下載未鎖版依賴。
- 不把 benchmark 當 PR gate；效能波動容易製造噪音。
- **不放任無上限 `-j`**（見 §0）。
